1. Vision / Visão

Extend MATLAB-like syntax for browser-based lumped-parameter modeling, combining procedural functions, behavioral models and generalized netlists. Specialized interfaces remain JavaScript applications contributed through pull requests. Metadata and UI are outside the modeling language.

2. Project structure / Estrutura

%% INITIAL_SCRIPT
% Imports, parameters, functions, models and reusable netlists
%% NETLIST
% Instances, connections and optional graphical layout
%% ANALYSIS_SCRIPT
% Simulation, analysis, plots and tests

All three sections may be optional. Importing a reusable model must not automatically run its analysis script. Projects may expose ports and parameters and use analysis as a testbench.

3. Proposed syntax / Sintaxe proposta

function y = f(u)
    y = sin(u);
end

model y = DeadZone(u)
    parameters
        delta = 0.1;
    end
    if u > delta
        y = u-delta;
    elseif u < -delta
        y = u+delta;
    else
        y = 0;
    end
end

model [theta,omega] = Pendulum(torque)
    parameters
        m=1; l=0.5; b=0.1; gravity=9.81;
    end
    states
        angle=pi/4; speed=0;
    end
    der(angle)=speed;
    der(speed)=(torque-b*speed-m*gravity*l*sin(angle))/(m*l^2);
    theta=angle; omega=speed;
end

model u = DigitalPI(e)
    parameters
        Kp=1; Ki=10; Ts=1e-3;
    end
    states
        x=0;
    end
    every Ts
        next(x)=x+Ts*Ki*e;
        u=Kp*e+x;
    end
end

netlist u = PIController(e)
    parameters
        Kp=1; Ki=10;
    end
    B1 Gain e up K=Kp
    B2 Gain e ei K=Ki
    B3 Integrator ei ui x0=0
    B4 Sum up ui u signs="++"
end

Named inputs, outputs, states and parameters follow the spirit of Python Control. Local and imported functions may implement f and g. Pure evaluations can repeat within solver steps; next stages simultaneous state updates. Sampled outputs hold between ticks. Exact event and initialization semantics remain open.

4. Physical models / Modelos físicos

model Resistor(p,n)
    ports
        electrical p,n;
    end
    parameters
        R=10;
    end
    equations
        p.v-n.v=R*p.i;
        p.i+n.i=0;
    end
end

netlist LCFilter(p,n,out)
    ports
        electrical p,n,out;
    end
    parameters
        L=1e-3; C=100e-6;
    end
    L1 Inductor p out L=L @pos=[100,50]
    C1 Capacitor out n C=C
end

Proposed acausal ports conserve flows and share potentials: voltage/current, temperature/heat flow, angular velocity/torque and velocity/force. Flow is positive into components. The equations block distinguishes simultaneous constraints from procedural assignments. DAE structural analysis and consistent initialization are unresolved implementation challenges.

5. Hierarchy, editor and libraries / Hierarquia, editor e bibliotecas

Use a canonical typed graph shared by textual netlists and graphical diagrams. Stable instance IDs, named ports, local labels, hierarchical paths, optional graphical attributes and automatic layout. Infer scalar/vector/matrix, real/complex/logic, units, reference frames, sample times and conductor groups; reject incompatible connections. Physical wires neutral, signal wires blue, redundant markings for three-phase and digital buses. Ideal voltage sensors are open circuits; ideal current sensors are series shorts. Probes do not alter topology.

import "models/LCFilter.eevl" as LCFilter;
% Example instance:
F1 LCFilter vin 0 vo L=2e-3

Native JavaScript models and language-defined models should share a contract. Version imports; reject recursive structural dependencies; review remote executable imports. Preserve hierarchy for analysis and editing.

6. Power systems / Sistemas de potência

Distinct power-flow, phasor dynamics, sequence and EMT representations. Three-phase Sbase and regional line-line RMS Vbase propagate through nominal transformer ratios, not taps. Distinguish rated and system bases; detect inconsistent regions. Zbase=Vbase²/Sbase; Ibase=Sbase/(sqrt(3)*Vbase). Explicit abc, dq0, alpha-beta-zero and sequence [0,1,2] conventions.

7. Digital and hybrid systems / Sistemas digitais e híbridos

Gates, flip-flops, registers, state machines, sampled algorithms, multirate clocks, events, delays, logic 0/1/X/Z, fixed-point arithmetic and overflow. Separate per-run random tolerances from temporal noise. Define simultaneous updates and zero-crossing semantics.

8. Device characterization / Caracterização de dispositivos

No ngspice integration in the browser runtime. External characterization scripts may extract conduction and switching LUTs, reduced models and thermal networks from SPICE or measurements. LUTs are parameters with axes, units, interpolation, validity and provenance. Validate independent cases and avoid double-counting switching/recovery losses.

9. Aerospace / Aeroespacial

CesiumJS as visualization adapter, not dynamics solver. Integrate quadcopters, aircraft, rockets and satellites from student projects using common time, position and orientation interfaces, glTF/GLB assets, trajectories, plots and playback. Explicit ECI/ECEF, NED/ENU, body, wind and orbital frames; document quaternion order and rotation direction. Validate coordinate transformations and numerical trajectories against reference models.

10. Proposed roadmap / Roteiro proposto

Parser and AST, typed graph, hierarchy elaboration, connection equations, structural analysis, solver scheduling and named results. Begin with procedural math, explicit ODEs, discrete blocks and simple MNA; expand to nonlinear DAEs, hybrid events, power flow, linearization, optimization and identification. No general PDE, FEM, CFD or FDTD solver in initial scope. Test numerical accuracy, text/diagram round trips, units, event timing and resource limits; avoid unrestricted eval. Grammar, DAE index reduction, initialization, events and import contracts remain open design work.
